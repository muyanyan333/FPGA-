# LYR2 歌词 + 歌名点阵格式

`tools/generate_lyric_bitmap.py` 从带歌词的源视频生成原始 LYR1 歌词帧；
`tools/prepare_card.py` 再把 LYR1 转换成 FPGA 当前使用的 **LYR2**：在歌词数据前
加入 1 KiB 前导区，并写入该曲的竖排歌名点阵。FPGA 不需要中文字库。

## 文件布局（所有偏移为字节，文件大小必须是 512 的整数倍）

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 32 | 头（见下表） |
| 32 | 480 | 保留（0） |
| 512 | 512 | 歌名点阵：16 px 宽 × 256 px 高，行优先 |
| 1024 | N × 1024 | 歌词帧 0..N-1，每帧固定 1024 字节 |

- 文件总长 = `1024 + N × 1024`。
- 歌词帧 N 从偏移 `1024 + N × 1024` 开始，正好占 2 个 512 字节扇区。
- 歌名块固定在扇区 1（文件首扇区 + 1），FPGA 启动该曲时读一次。

## 32 字节头（小端）

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 4 | ASCII `LYR1` |
| 4 | 1 | 版本 = 2 |
| 5 | 1 | 标志 = 0 |
| 6 | 2 | 宽度 = 512 |
| 8 | 2 | 高度 = 16 |
| 10 | 2 | 帧间隔 = 500 ms |
| 12 | 4 | 歌词帧数 N |
| 16 | 4 | 原视频时长，ms |
| 20 | 4 | 歌词数据偏移 = 1024 |
| 24 | 1 | 原始曲目号（1～16）。FPGA 优先用文件名前两位数字配对；文件名不是数字开头时才回退到这个字段 |
| 25 | 7 | 保留 |

FPGA 在开始播放时校验 `LYR1`、`data_offset==1024`、`frame_count>0`、文件大小为
512 的整数倍，并要求 exFAT 文件连续（NoFatChain）。校验失败时只播放音频，
不显示歌词/歌名。

## 歌名点阵

- 16 像素宽 × 256 行，共 512 字节；每行 2 字节，MSB first。
- 每行第 0 字节的最高位对应最左侧像素（x = 0）。
- 最多 16 个 16×16 字模，自上而下竖排并整体垂直居中。
- 由 `prepare_card.py` 使用 `C:\Windows\Fonts\msyh.ttc` 以 16 px 渲染后二值化；
  文字来源是 `playlist.csv` 的 `title` 列（即 MP4 文件名里的歌名）。

## 歌词来源：优先使用 LRC

### 当前卡上的 v2 抽取

如果暂时没有 LRC，`tools/generate_lyric_bitmap_v2.py` 会从你自己的 MP4 里重新抽取：
竖屏歌词视频的当前行基本固定在画面约 73% 高度处，脚本只截取这一行，输出单行、
无重影的 512×16 点阵；横屏的 03（你走以后）保留旧抽取结果。生成后运行：

```text
python tools/generate_lyric_bitmap_v2.py
python tools/prepare_card.py --lyrics lyric_build_v2 --skip-images --skip-housekeeping
```

v2 不会改变文字内容，只是把视频里的当前歌词行单独取出来；如果某句仍然对不上，
最可靠的方案仍是提供 LRC。

### 交互式粘贴工具

`python tools/paste_lyrics.py` 可以一次处理多首：

- 输入歌名或曲目号，粘贴歌词，单独一行 `END` 结束该首；
- 自动识别标准 LRC、`mm:ss.xx` 前缀和纯文本三种格式；
- 纯文本可指定首句时间和每行间隔，或按 WAV 时长自动均分；
- 生成 `lyrics_lrc/NN.lrc`，结束后可选择直接运行 `prepare_card.py` 渲染并写卡。

脚本只打印时间轴/文件等元数据，不回显歌词内容。

从源视频抽取的点阵会有重影、背景残影和同屏多行，清晰度有限。当前推荐：

1. 把每首歌的 `.lrc` 按 `01.lrc`…`12.lrc` 放进 `lab_ex5_i2s-work/lyrics_lrc/`。
2. 运行 `python tools/prepare_card.py`；脚本会优先用 LRC，把当前时间点对应的
   一句歌词用**统一的 16 px 字体**（2× 超采样后二值化）渲染到 512×16 点阵，
   并保留原来的 500 ms 帧间隔。
3. 没有对应 LRC 的曲目才回退到视频抽取的 LYR1 点阵。

LRC 支持 `[mm:ss.xx]`、多时间标签、`[offset:±ms]` 和空行清屏。
歌词文本的版权归原权利人所有，工具只负责渲染你提供的文件。

## 与音频的时间对齐

- FPGA 每收到 24 000 个 48 kHz PCM 帧（500 ms）前进一帧歌词。
- 只有音频真正从 I²S 输出时才会产生 PCM 帧计数；暂停时歌词冻结，
  切歌/重新开始时回到第 0 帧。
- 计数从本曲音频开始输出时起，头校验通过后即使首帧还在加载，期间到达的
  PCM 帧也计入，避免开场歌词滞后。首帧加载只需约 2 ms。
- `prepare_card.py` 会校验每首歌的 LYR 时长与对应 WAV 时长差 < 0.15 s。

## 屏幕位置

- 歌词条：`x = 64..575`，`y = 2..17`，白色文字，顶部整条背景压暗到 1/4。
- 歌名条：`x = 608..639` 压暗，文字列 `x = 616..631`，`y = 112..367`，
  颜色 `24'hFFE080`。
- 音乐模式下不显示左上角的上电计时；手机通知仍在 `y = 36..60`。
