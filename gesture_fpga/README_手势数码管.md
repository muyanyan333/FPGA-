当前发送板位流：`src/td_project/camera_gesture_link_seg.bit`。
构建：`src/td_project/build_camera_gesture_link_seg.tcl`。
工程及顶层继续为 `full_camera_edge_preview.prj` / `top_camera_preview`。

本次只替换摄像头识别板当前数码管显示。接收板不需要重新下载；J2 第19脚/G1 UART 及四种动作协议保持原样，接收代码仍在 `receiver/`。原有摄像头、背景处理、静态分类、挥手检测、HDMI 和按键逻辑均保留。

## 显示规则

按板上现有扫描顺序，从第1位到第8位（SEL[0]～SEL[7]）：

| 当前识别状态 | 唯一显示位置 | 内容 |
| --- | --- | --- |
| 张手 OPEN | 第1位 | 1 |
| 握拳 FIST | 第2位 | 2 |
| 左挥 LEFT | 第4位 | L |
| 右挥 RIGHT | 第5位 | r，表示 R |
| NONE / UNKNOWN / MULTI / BGCHECK / 背景未就绪 | 全部 | 熄灭 |

第3、6、7、8位始终不显示。小数点始终关闭。七段数码管不能完整画出大写 R，所以使用常见的 r 形（e、g 两段点亮）表示右挥；L 使用 d、e、f 三段。

数码管使用当前已确认的显示状态，没有独立的“上次手势”锁存。没有确认左挥，不会产生 L。LEFT 切换到 RIGHT 时第4位立即关闭，随后仅第5位显示 r；离开有效目标或重新记录背景时立即全灭。不会把 UART 最近收到/发出的编号当作当前识别结果一直显示。

挥手的有效提示窗口沿用原识别版约1秒的 LEFT/RIGHT 显示时段，新确认的方向会替换旧方向；本次没有修改挥手识别阈值、冷却或保持时间。无有效目标时数码管直接熄灭，即使 HDMI 还在短暂保留最近一次挥手提示。

## 硬件

沿用原有数码管引脚及低有效段码、位选扫描，无新增接线。第1、2、4、5位分别使用原来的 SEL[0]、SEL[1]、SEL[3]、SEL[4]。SW6 保持数码管挡（手册说明拨上接通数码管，拨下接双色 LED）。引脚及段结构依据原工程和用户提供的 HX4S20 手册核对。

显示驱动和识别状态同属 25MHz 视频时钟域，避免多位状态直接跨时钟采样造成假字。切换状态时还会按当前位选立即消隐旧字，扫描换位保留原模块的消隐时间。

## 验证

`sim/tb_gesture_sevenseg.v` 验证四种位置/段码、其他位关闭、未知/无目标/干扰状态全灭、扫描中 L→R 立即清除旧字及复位全灭。

`sim/tb_gesture_display_state.v` 验证实际视觉显示接口到数码管状态的连接、左右方向替换、目标丢失和背景重录清除。真实识别是否正确仍由现有视觉算法决定，数码管只反映其结果。
