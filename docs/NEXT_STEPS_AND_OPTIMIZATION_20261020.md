# 本轮优化与创新方向

## 已完成的优化

### 摄像头模式回传使用发送快照

原来的 `uart_image_control.v` 在生成 0x86 状态帧时直接读取实时 `camera_mode`。如果切换发生在模式数据字节发出后、校验字节发出前，数据和校验会来自不同的模式，手机会丢弃该帧，可能延迟操作确认。

现在与图片、音乐和音量状态一样，在开始发送一轮状态前保存模式值；该轮数据与校验都读取同一个快照。发送期间的模式变化仍会置位待发送标志，下一轮发送最新状态。UART 协议、按键功能和接线不变。RTL 增加一个状态位，不新增帧缓存；实际资源变化需要重新综合确认。

新增 `src/test/uart_camera_status_snapshot_tb.v` 从 UART 输出引脚解码字节，在 0x86 模式字节收到后切换模式。旧版失败：数据 `00` 的预期校验是 `DC`，实际收到 `DD`。修复后，0→1→0 两次切换的帧校验与后续状态均正确，测试的每位时钟周期数为 10 和 17。

### 通知发送绑定原始连接

网页原来在通知任务出队时才读取写特征。若任务排队期间断开并重连，旧通知可能发送到新连接。现在入队时保存连接编号和写特征，在每个分包发送前后、最后一个分包结束以及延迟查询前检查连接。过期任务不再写入新连接，也不会把旧任务结果显示成新连接的发送成功。

同时忽略通知尚在发送期间的重复提交。两份网页入口和 Android 内置页面已同步；Android 版本为 2.0.2，versionCode 22。

新增 `android_app/test_notice_connection.cjs`，旧版在排队重连场景向新连接写出 52 个分包；修复后为 0。覆盖正常 1029 字节通知及校验、排队重连、最后一包期间重连、延迟查询期间重连和重复发送，网页与 Android 内置页面均通过。

历史 setup WNS 为 −6.826 ns，hold WNS 为 −1.540 ns，尚未时序收敛。最差 setup 路径涉及 SDRAM 相关的相移时钟之间的数据传输，另有存储器域内部和跨域路径需要核对。应结合 SDRAM 工作时序、PLL 相位和同步电路逐项处理，不能仅通过扩大 false path 或异步时钟分组来掩盖问题。

## 建议增加的功能

以下均为设计建议，尚未实现；资源成本是定性判断，需综合和布局布线后验证。排序兼顾演示效果、现有接口和资源余量。

| 方向 | 可演示的效果 | 最小实现方案 | 成本与约束 |
| --- | --- | --- | --- |
| 场景编排 | 点一次“展示”“听歌”“讲解”，连续设置图片模式、音量、字幕和显示属性；手机保存并恢复自己的场景 | 在 Android/网页保存设置组合，复用现有明确设值命令，逐项等待状态确认；失败时显示未完成的步骤 | 首版可不增加 FPGA 逻辑；需要处理模式切换复位、命令队列与超时；是多步执行，不能宣称原子切换 |
| 摄像头区域变化检测 | 摄像头画面出现运动时，在对应区域提示，并向手机发送事件 | 先在摄像头模式做 32×24 灰度抽样，比较前后帧差值，连续多帧达到阈值再触发；先做区域变化，不宣称人脸或手势识别 | 32×24×8 位历史样本为 768 字节，理论上可容纳于一块 9Kbit RAM，实际映射与其他逻辑另计；曝光变化、抖动会误触发，需要阈值、去抖和冷却时间 |
| 音乐节奏联动画面 | 频谱之外增加随能量变化的边框或色彩；自动模式下按节拍请求切图 | 复用已有 FFT 或 PCM 能量，做平滑、阈值和最小触发间隔，不再新增 FFT 核 | 需要 RTL 与视频帧边界同步；手动模式不得自动切图，且不得在当前转场未完成时连续触发；效果应先验证，不能保证音乐节拍识别准确 |
| 设备诊断页 | 手机直接看到摄像头实际完成帧率、丢帧次数、音频欠载次数和最近有效状态时间 | 给采集完成、坏帧、FIFO 溢出/欠载事件加计数，通过低频状态帧回传 | 需要少量计数器、跨时钟域快照和协议扩展；帧率统计以完整帧为准，错误按事件计数，不能把持续高电平逐周期累计 |

建议先做“场景编排”，用已有协议形成完整的演示流程；如果希望增加更有 FPGA 特点的亮点，再做“摄像头区域变化检测”。

目前摄像头在图片音乐模式会被复位停用，因此“人在镜头前走过就自动进入展示”还需要调整双模式的数据通路，不能当作现成摄像头检测的附带功能。

帧差与阈值是可组合的基础图像算子，可参考 [AMD Vitis Vision API](https://docs.amd.com/r/en-US/Vitis_Libraries/vision/api-reference.html) 理解处理步骤。该库面向 AMD 平台，本项目使用 Anlogic，不能直接把它当作本工程可用 IP；这里的资源预算仅针对拟实现的简化 RTL。
